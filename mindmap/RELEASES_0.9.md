**Entry:** the V0.9.0 to V0.9.32 jobs and the confirmation model exist. V0.9.34 to V0.9.38 change no behaviour a person sees.

**Exit:** in Agent mode CAIRN chains read tools, proposes changes that people confirm, cites only what it read, remembers in governed layers and works across workspaces without crossing a workspace's AI boundary; each model the guides name has a passing live evaluation; CAIRN is administered from its own page: models come from one server catalog, organizations choose them and workspaces narrow them, people pick a model per chat, and guardrails, abilities, instructions and preferences are set at the tier they belong to; the CAIRN and CAIRN administration security reviews have no open high or medium finding; every row is ✅ or narrowed in the guides.

**Scope control:** CAIRN gets no outside MCP tools, shell, web or outbound messages in this line, routines never apply changes, and nothing CAIRN writes by itself steers anyone else's runs. Custom abilities are instructions over the registered tools and never add a tool, an external effect or a right; administrators see settings and aggregates, never conversations ([ADR 0007](../docs/decisions/0007-cairn-models-are-a-system-catalog-chosen-per-organization.md)). The [plan](plans/2026-11-22-0.9-cairn-harness.md#excluded-on-purpose) lists what would reopen each exclusion.

## Verification and handoff

Before opening the 0.10 line, record the CAIRN walkthrough with a real provider, a live evaluation report for every model the guides name, the injection and cross-workspace negative cases, and the deletion and anonymization of traces, personal memory and chat search. Tests must demonstrate the user outcome, including failure and recovery. Follow the repository's execution rules; unrun checks remain explicitly unrun and the maintainer supplies live evidence.

Any new storage field, enum or entity must include its archive compatibility and migration handling in its own implementation. CAIRN's personal data (chats, traces, personal memory, chat search, shares, routines, inbox) is not part of workspace archives and is removed by account anonymization; memory cards, notes, playbooks and `CAIRN.md` are ordinary workspace content and travel with archives.

When a row ships, update this index and the matching roadmap row together; put the actual behavior and limitations in the changelog. The version range is an ordered plan, not a calendar forecast.
