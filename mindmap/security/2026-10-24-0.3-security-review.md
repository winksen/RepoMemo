## 1. Who may do what on the new routes

| Route | Guard | Checked |
|---|---|---|
| `POST /v1/artifacts/{id}/versions/{n}/restore` | `AuthenticatedSubject` (a read-only token is refused), write access to the file's workspace, not a repository file | The version is looked up in the file's own list, so another file's number is a `404`; its size counts against the allowance again before anything is written; the restore is one activity entry |
| `GET /v1/artifacts/{id}/code-owners` | read access | The owners are matched among the workspace's members only; a handle or a team stays a hint and is never guessed |
| `POST /v1/artifacts/{id}/review-requests` | write access | Only a member that `CODEOWNERS` names for that file can be asked, once while the task is open; the note is 1,000 characters at most |
| `POST /v1/search` (all workspaces) | `ReadingSubject` | Each workspace is searched with the caller's own role there (`effective_workspace_role`) and its AI policy; a list of workspace ids only narrows; the heavy quota applies |
| `POST /v1/workspaces/import` and `GET /v1/workspaces/import/jobs/{id}` | `ManagingSubject` (V5) | A job is its owner's (or a system administrator's) and anyone else gets a `404`; the id is a long random secret; V3, V4 |
| `GET /v1/{connectors,repositories}/{id}/webhook/deliveries` and `…/{delivery}/resend` | write access to the source's workspace | The delivery is looked up under the source's id, so another source's delivery is a `404`; only a call that asked for a sync can be sent again; ten a minute for a source; V9 |
| `POST /v1/system/backups/{name}/reseal` | full system administrator, `require_system_change` | The name is one the server wrote; one backup or restore at a time; the key checks come first; §7 |
| `GET /v1/system/backups` | system administrator | Which key opens each backup is worked out once for each way of sealing and remembered; the passphrases are never in the answer |

## 2. Restoring a version

The restore is a copy of an older version's bytes into a new version: it reuses a stored file by its hash, so nothing is read from outside the store, and it cannot restore into another file because the version number is looked up in this file's own history. A repository file is refused (its content is the repository's). A viewer, a read-only token and a stranger are refused before anything is read. The quota check uses the version's own size, and the restored text is indexed again like an upload.

## 3. Mentions and review requests

A mention is read from the text with a split on white space and `@`; only members of that workspace are looked up, the author is never told, and a person already mentioned in the earlier text is not told again (V12). Nothing in the answer to the writer says whether an address is a member, so the names of a workspace cannot be probed. The notification and the mail carry the title of the place, shown as text. A review request is the same task and the same notice as an assignment; it is limited to the owners `CODEOWNERS` names and to members.

## 4. The import as a job

| Concern | What happens |
|---|---|
| Who can ask | A session or an `admin` token of an organization owner or administrator with a verified account and room for a workspace; the same checks as before, in the same order, before a byte is read |
| The place | One import running for a person, two on the server (V3: taken before the body is read) |
| The job | In memory: its owner, its stage, bytes done and, when it ends, its report or its reason. Kept an hour, five finished ones for a person and a hundred in all (V4). A restart ends them and creates nothing |
| Who reads it | Its owner or a system administrator, with a session or an `admin` token (V5); an unknown or foreign id is the same `404` |
| What it can do that the request could not | Nothing: it runs the same reading with the same checks. Its stage and progress are two integers and a word from a fixed list |
| The files | The temporary file is removed when the reading ends, as before; leftovers older than a day are swept by the next import |
| The sizes | Taken from the stored files, not from the records (V6) |

## 5. References between items and approvals

Items are resolved in the workspace they belong to (`list_connector_item_metadata(workspace_id)`), so a reference can never point at another workspace's item, and an address resolves only when a stored item has exactly that address. A number that two items share is not guessed. A text is read in one pass (V1, V2). GitLab's approvals come from a call that, if it fails for any reason, leaves the merge request without approvals and never pauses the connector; the approver names are shown as text.

## 6. Webhook deliveries

Only calls that were signed right are kept (a call that cannot be verified says nothing about the source and is not stored), a repeat of a delivery id is not stored, and a source keeps its newest hundred, so neither an outsider nor a replayed call can fill or push out the list. The event name (80 characters), the delivery id (128) and the reason (400) are cut before they are stored and are shown as text. A resend asks for the sync through the source's own runner, so the pause for the tracker's rate limit, the room check and the one-at-a-time rule apply as to any sync.

## 7. The backup passphrase

`REPOMEMO_BACKUP_KEY_PREVIOUS` is read once at start, must be 16 characters or more, different from the current key and set only with it, and is never logged, listed or returned (the configuration is not printed anywhere). A restore tries the current key and then the previous one, and a wrong one is refused with the same message before any folder is made. Sealing again reads the files with the previous key and writes them with the new one chunk by chunk, so the plain text is never whole in memory and never on the disk; the new folder is made beside the original and swapped in only when whole, the original put back if the swap fails; the key file stays owner-only; a second copy that was made before is replaced because its manifest is no longer the backup's. The free-disk check runs first.

## 8. The removal of the local edition

The desktop crate now has eight commands and no plugin but the HTTP one: no filesystem, shell, dialog or process access is granted by the capabilities (`core:default`, and `http:default` scoped to the chosen server at run time). The window is created in code so that it can refuse to leave the bundled client (`on_navigation` allows only the app's own addresses and, in a debug build, the development server), the content security policy keeps `script-src 'self'` and `connect-src` to the app and its own IPC, the refresh token lives in the system's credential store and not in a file or the page's storage, and a server address must be https unless it is on the person's own network (V8). `open_external` opens only `http` and `https` addresses and passes the address to the system as one argument, never through a shell.

## 9. Looked at and found fine

- Every new text is rendered by React as text; the skip link, the toolbars and the delivery lines have no markup from outside.
- No new SQL is built from a request: the deliveries and the mentions are written with bound parameters, and the migration (0043) has foreign keys that remove its rows with their source.
- The new routes were added to the tests that refuse a read-only, a read-and-write and a system token on routes that need the `admin` scope (the import job now among them).
- Format 2 archives are checked as format 1 were: every stored file a version names must be listed, present and match its hash; a version number below 1, repeated or without a file is a problem.
- The all-workspaces search never takes a role from the request.
