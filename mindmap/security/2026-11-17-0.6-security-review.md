# Security review of the 0.6 knowledge surfaces — 2026-11-17 (V0.6.29, on what V0.6.2–V0.6.28 added)

> **Scope:** My work (V0.6.2); memory card revisions, compare, restore and the cited-source reader (V0.6.3, V0.6.10, V0.6.19); stale-save refusal and drafts (V0.6.4, V0.6.5); review ownership and reminders (V0.6.6, V0.6.7); approvals and the independent-review rule (V0.6.8); revision attribution and imported history (V0.6.11, V0.6.12); knowledge archives and their round trip (V0.6.14, V0.6.28); trash and restore (V0.6.15); write preconditions (V0.6.18); organization templates (V0.6.23); folder move preview (V0.6.24); search feedback (V0.6.25).
> **Method:** a static reading of the code at `V0.6.28`, asking of each route and each stored record who may reach it, what a person with less access could learn or change through it, what a token with a narrower scope could do, what a crafted archive could carry, and what stays behind after a delete. Nothing was built or run, and no test was executed.
> **Status:** closed on 2026-11-17 at `V0.6.29`. **0 high, 1 medium, 3 low, 5 info:** the medium and the three lows are fixed; none is open. The informational findings are accepted and written down.
> **Previous review:** [2026-10-29, identity](2026-10-29-identity-review.md).

## 1. Who can reach what

| Surface | Read | Change | Checked in |
|---|---|---|---|
| My work | the caller's own work only, with revoked workspaces dropped and workspace-limited tokens held to their workspaces | — | `my_work.rs` |
| Revisions, compare, cited source, changes | `require_workspace_read` on the card's workspace (a card the caller cannot read looks absent) | restore: `require_workspace_write` | `card_workspace`, `memory_history.rs` |
| Approvals | read access | approving or withdrawing: a writer who is not the card's reviewer or an administrator is refused; the independent-review rule and the revision the caller read are checked in the write; the rule itself: administrator **and** session or admin-scope token (S1) | `approvals.rs` |
| Review ownership | read access | write access; the reviewer must be a member who can edit | `review_ownership.rs` |
| Trash | `require_workspace_write` | restore: write access and the allowance (S2); purge: administrator and session or admin-scope token (S1), audited | `trash.rs` |
| Archives | export: administrator and session or admin-scope token; import: organization owner or administrator | an import never creates accounts, never carries an approval as a decision, and rechecks the template and the reviewer | `workspace_export.rs`, `workspace_import.rs` |
| Organization templates | any member of the organization lists its templates; another organization's are absent | administrator and session or admin-scope token (S1); the text is held to the template rules, ids are owned by the first organization that saves them | `organization_templates.rs`, `templates.rs` |
| Search requests | the asker sees their own, administrators see all of the workspace | any reader can send (25 open at most); answering: administrator and session or admin-scope token (S1); the answer must name evidence or a card of the same workspace | `search_feedback.rs` |
| Folder move preview | write access | — (the preview changes nothing) | `artifacts.rs` |
| Drafts | this browser tab's session storage, keyed by server and person, cleared at sign-out and on a server switch | — | `lib/drafts.ts` |

## 2. What a crafted archive can carry

Revisions, approvals, reviewers and templates arrive as data in `workspace.json`, after its checksum and size checks. A revision's citation names a file by the archive's own id, and an id the archive does not define becomes "gone"; nothing in it can name a file of another workspace. An approval is written to a separate table and is never read by the approval rule. A reviewer is an address that must belong to an existing member who can edit, or only a name. A template reference that the target organization cannot use is dropped and reported. The only unbounded lists are the ones the archive's overall size limit already bounds.

## 3. Negative cases and their tests

| Negative case | Test (written; not executed) |
|---|---|
| Someone outside the workspace reads revisions, a cited source, a card's changes or search requests | `citation_durability`, `memory_history`, `card_changes`, `search_feedback` |
| A guest decides, restores, restores from trash, previews a move or purges | `approvals`, `trash`, `folder_move_preview` |
| A person approves their own revision under independent review | `approvals` |
| An approval of a revision the reviewer did not read | `approvals`, `edit_conflicts` |
| An imported approval counts as a decision | `knowledge_archive`, `archive_roundtrip` |
| Another organization sees or adopts an organization template, in the picker, by id or through an import | `organization_templates`, `archive_roundtrip` |
| A write token makes an administrative change | `knowledge_token_scopes` (new) |
| Work in a workspace the person left still shows | `my_work` |
| A stale write overwrites a newer one | `edit_conflicts`, `write_preconditions` |
| A search request answered twice, or with something outside the workspace | `search_feedback` |

Not covered by a test: S2 (the allowance on restore), S3 and S4 (not reachable through the API).
