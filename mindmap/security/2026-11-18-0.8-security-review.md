# Security review: connectors, outbound webhooks and chat delivery (V0.8.15)

> **Date:** 2026-11-18 · **Code:** V0.8.14 reviewed, fixes in V0.8.15 · **Line:** [0.8 plan](../plans/2026-11-18-0.8-connections.md) · **Release row:** [V0.8.15](../RELEASES_0.8.md)

## Scope and method

The surfaces added or changed in 0.8.0 to 0.8.14: the connector preview and approval (0.8.1), quarantine (0.8.2), health and checkpoints (0.8.3), signed outbound webhooks (0.8.4), the Jira adapter and its lifecycle (0.8.5, 0.8.6), follow-up links (0.8.8), Slack digests (0.8.9), the directory and Confluence importers (0.8.11, 0.8.12), AI usage limits (0.8.13) and the answer rules (0.8.14). Read the code for each, looking for: a path that serves content the audience was not approved for, a request the server can be made to send somewhere it should not, a secret that leaves the server or is kept in the clear, a limit that can be skipped, and input that is trusted. **This is a review by reading the code and reasoning about it. Nothing was run, no scanner was used and no penetration test was done.** The regression tests named below compile and were not executed.

## Rules for public publishing (written before V0.8.16 starts)

The 0.8.16 to 0.8.18 rows add routes anyone on the internet can call. They are built to these rules; a change to a rule is a change to this document first.

1. **A separate store, read by separate routes.** A publication is a **copy** in tables of its own. The public routes read only those tables and never join to files, memory cards, comments, accounts or workspaces. A bug in them cannot reach private data because the data is not there.
2. **Only what a person reviewed.** A snapshot is made from the text an authorized publisher previewed, and kept as that text. A later change to the private original never changes the snapshot; the publisher publishes again to update it.
3. **Excluded unless independently approved:** citations, comments, attachments, people (names, emails, avatars), paths, source and connector names, internal identifiers, dates that reveal activity, and the workspace's name. Public pages use opaque public addresses, never a file, task or workspace id.
4. **Private references are removed, not linked.** A link in a snapshot to something that is not published is replaced by its text with no address; it never exposes a private address or id. A link to another published page may be kept.
5. **Anonymous routes are plain.** Under their own prefix (`/public`), `GET` only, no cookie read or set, no `Authorization` considered, no query text reflected unescaped, a small request limit, and a rate limit per address. Responses carry `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and a Content-Security-Policy that allows no script. Content is rendered by the same sanitizing Markdown renderer as the app, never inserted as HTML.
6. **One answer for everything that is not served.** An unpublished, withdrawn, unknown or malformed address is the same `404`, so existence is not learned; search and index results, counts and errors are made from published snapshots only.
7. **Caches never outlive a withdrawal.** Pages are `Cache-Control: public, max-age=60, must-revalidate` with an `ETag` of the publication's version, never `immutable`; `404` and `410` are `no-store`. Withdrawing, and a source being revoked, take effect at the next request and at most one cache lifetime later at a shared cache, which the publisher's preview states.
8. **Revocation unpublishes.** When a source a snapshot was made from is quarantined or removed, the publication is marked stale and stops being served until a publisher confirms it again (V0.8.17).
9. **An operator switch, off by default.** `REPOMEMO_PUBLIC_PUBLISHING` must be turned on for the routes to exist; off, they answer `404`. A publisher needs the administrator right of the workspace, and every publish and withdrawal is recorded with who did it.
10. **Nothing personal is logged for readers.** Anonymous reads are counted in aggregate for the operator; no address, agent or query is kept beyond the rate limiter's short window.

## What was not reviewed

The Jira site itself, the behaviour of a real tracker's rate limits and permission replies, Slack's webhook semantics, the operator's network and egress rules, the web client's rendering of imported Markdown beyond reading that it uses the sanitizing renderer, and anything that runs only at deploy time.
