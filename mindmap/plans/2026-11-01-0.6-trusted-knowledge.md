# Plan: the 0.6 line, trusted knowledge in daily work

> **Opened:** V0.6.0 (2026-11-01) · **Index:** [0.6 releases](../RELEASES_0.6.md) · **Report gaps:** G04–G08, G13 · **Entry:** the [0.5 access model](../RELEASES_0.5.md) is built.

The line makes a teammate reach value without AI, recover from an interrupted or conflicting edit, review a changed conclusion, undo a deletion and do all of it by keyboard. This plan fixes the two journeys and the words the product uses for knowledge state, so each release uses them the same way.

## The two journeys

**First value (no AI, no mail).** A new member opens a workspace → sees a checklist built from the chosen template and from real source readiness → adds evidence → finds it by search → saves a cited memory card. Progress is derived from what exists (an artifact, an indexed file, a card with a citation), never from clicks. Releases: 0.6.1, 0.6.2, 0.6.12–0.6.16.

**Knowledge review.** Evidence changes or a review date passes → the card needs review → its accountable reviewer sees what changed, resolves each affected citation in context, and approves a specific revision → the history shows who decided what, and an earlier conclusion can be restored as a new revision. Releases: 0.6.3–0.6.11, 0.6.18.

## State terminology

| Word | Meaning | Never means |
|---|---|---|
| **Revision** | One saved version of a card's text and citation set, numbered from 1, attributed, immutable | A git commit or an uploaded-file version (those are *file versions*) |
| **Draft** | Text a person has not saved; kept in that person's browser session only | A saved revision, or anything another person can see |
| **Needs review** | The card's cited evidence changed or left use, or its review date passed | Rejected or wrong |
| **Overdue** | The review date passed; says nothing about the evidence | Changed evidence |
| **Changed evidence** | A cited file changed, was retired or was deleted since the card was last checked | A late reviewer |
| **Approved** | A named reviewer accepted one specific revision; any edit makes it unapproved | Verified by an automatic check |
| **Reviewer** | The person accountable for checking a card or file; may differ from the owner | An administrator by role |
| **Trash** | A bounded holding place for deleted local content, restorable until purged | A backup or an archive |
| **Conflict** | A save based on an older version than the current one; refused, never merged silently | A failed network request |

Ownership and approval: the **owner** keeps the item and may delegate its **review**; an **approval** is tied to a revision and, when the workspace requires independent review, cannot be given by the person who made that revision.

## Representative fixture

`apps/server/src/tests/knowledge_fixture.rs` builds the situation every 0.6 test starts from:

| Part | Why |
|---|---|
| No AI provider configured | The journeys must work without one |
| No mail server | Reminders and digests must degrade to the inbox |
| An owner, a member and a guest (viewer of this workspace only, no organization membership) | Permission filtering, revocation and counts |
| Current evidence ("Deploy checklist"), searchable | The first-value path |
| Evidence retired by its lifecycle ("Refund policy") with a card citing it | Stale evidence → needs review |
| Evidence deleted after it was cited ("Retired runbook") with a card citing it | A missing source |

## Order and rules

- One release, one commit, in the order of the [index](../RELEASES_0.6.md). Each new table or field carries its archive handling ([0.6.18](../RELEASES_0.6.md) checks the whole journey).
- Local OCR (0.6.13) needs a pilot owner. No owner exists, so it ships as a bounded optional feature behind a setting that is off and states its limit, or as a recorded deferral; the guides say which.
- No release adds a mandatory AI or mail dependency.
- Tests are compiled and linted, not executed; live walkthroughs are recorded as pending in 0.6.19.
