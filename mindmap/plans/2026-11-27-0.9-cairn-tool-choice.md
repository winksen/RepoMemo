# Plan: CAIRN chooses its own tools

Written 2026-11-27 for V0.9.127. Baseline: V0.9.126. Scope is rows V0.9.127 to V0.9.145 in the [release index](../RELEASES_0.9.md) and the [roadmap](../ROADMAP.md#the-09x-line-cairn-agent). It continues the [CAIRN harness plan](2026-11-22-0.9-cairn-harness.md) and the [administration plan](2026-11-26-0.9-cairn-administration.md). Decision: [ADR 0008](../../docs/decisions/0008-cairn-asks-the-model-first-whenever-there-is-one.md), which amends [ADR 0006](../../docs/decisions/0006-cairn-is-a-bounded-tool-loop-over-governed-evidence.md).

This plan is written for the session that implements it. Each row below is one commit named `Update V0.9.N`, with the usual body (three or four `- ` lines, no trailer), the version set with `npm run version:set -- 0.9.N`, the changelog, the user guide when something visible changes, and the roadmap, release index and mindmap rows updated together. Follow [CLAUDE.md](../../CLAUDE.md): no server, build, Vite or Tauri run; ask before `cargo check` or `npm run typecheck`; run `cargo fmt --all` and clippy with `-D warnings` before a commit that touches Rust. Errors and outcomes are toasts; greys are pure ([DESIGN.md](../../DESIGN.md)).

## Why

A person asked "analyze the size of files in this repo". The keyword router matched *Analyze files*, took "the size of files in this repo" for a file name and answered "No file name or path matches", labelled *matched from your wording*. No model read the message. Even in Agent mode the model could not have answered: no tool knows file sizes, sorts files or counts them.

The goal of this plan: whenever a model is available, the model reads the request and chooses among CAIRN's tools, and those tools are general enough, and described well enough, for the model to choose well. Keywords remain only for the case where there is no model.

## The contracts this plan rests on

### 1. What answers a message

| The person has… | CAIRN answers with… |
|---|---|
| A model with native tool calling | the loop, natively |
| A model with JSON tool calling, or whose tool mode nobody set | the loop on the JSON protocol |
| …and the JSON protocol fails twice in a run | the model picks one job, the job runs, the model answers from its result (*the one-job path*) |
| A model set to `none`, or Jobs chosen by the organization, the workspace or the person | the one-job path |
| No model (none enabled, AI policy, quota spent, provider unreachable) | the keyword router, and the reply says it was answered without AI |

The keyword rules and template phrases run **only** in the last row. A picked job, a greeting and an uploaded file follow the same table.

### 2. The one-job path

1. The model classifies the message (`route_by_model`, today's prompt with the tools' descriptions of V0.9.139).
2. The job runs as today.
3. A job that did not itself write with the model (find files, find a symbol, search, list, recall) hands its result to the model with the message; the model writes the reply, says when the result does not answer the question, and keeps the job's citations. A job that already wrote with the model (Ask, summarize, analyze, overview) is not written twice.

### 3. Tools for the model

- **General tools that combine** sit beside the jobs. The new one is `query_files`: filters (text in title or path, kinds, folder, language, modified after or before, size at least), a sort (size, modified, created, name; either direction), a limit, and optionally a grouping (kind or top folder) with counts and total size. It is a read tool, also served over MCP.
- **Each description** says what the tool does, when to use it, when to use another tool instead, and what it returns.
- **A miss names the way forward**: the closest matches by name (`match_files`) and the tool to try next.

### 4. Labels

- No reply says how it was routed.
- One standing line under the message box: *AI responses can be inaccurate. Check the cited sources.*
- A reply made without a model carries *Answered without AI* and the reason (no model, AI policy, quota, provider unreachable).
- `AgentReply.routing` and `generated` stay in the API for traces and chat options; only the panel stops showing them.

## Before you start

Run `npm run cairn:eval` on the model you use, at V0.9.126, and keep the report. This is the baseline that V0.9.145 compares against. It is the maintainer's run.

### Track BA. Model first

**V0.9.128 🔧 Unknown tool mode tried as JSON.**
- `ModelTraits::from_metadata` keeps `None` for an explicit `"none"` and reads a missing `tool_mode` as `Json` for CAIRN. `ModelTraits::is_known` is unchanged, so the settings form still shows "not set".
- The connection test (V0.9.35) still records `native` when a model answers a tool call; nothing else changes it.
- Tests: missing → JSON; `"none"` → None; `"native"` → Native.

**V0.9.129 🔧 Agent mode whenever the model takes tools.**
- `cairn_mode_with`: an explicit `jobs` → jobs; otherwise any tool mode other than `None` → agent. The default list and the catalog pass stop deciding (`agent_default_for` and `catalog_model_passed` stay for V0.9.144).
- `OfferedModel.agent` and the settings form follow the same rule; the error "Agent mode needs a model that takes tools" only fires for `none`.
- Tests in `ai.rs` (`provider_metadata_tests`) rewritten: an unlisted native model and a JSON model are agent, an organization or person choosing Jobs keeps jobs.

**V0.9.130 🔧 One-job fallback when the JSON protocol fails.**
- In `loop_with`, an `InvalidToolReply` (already retried once by the provider layer) no longer ends the run partial: the run records the step, then takes the one-job path of contract 2 with the same message and returns its reply, with a trace step *Fell back to one job*.
- Tests with `ScriptedProvider`: two unreadable replies → a job runs and the reply is the job's; a readable reply after one failure → the loop continues.

**V0.9.131 🔧 The router asks the model before keywords.**
- `run_agent_router`: with `provider_id`, `route_by_model` runs first; the rules and template phrases run only without a provider, or when the provider fails (with the warning as today).
- A routed reply's `routing` stays `model` or `rules`, for traces.
- Tests: the router tests in `agent/tests.rs` run without a provider (they test the no-AI path); a scripted provider that classifies "analyze the size of files" as list files wins over the keyword match.

**V0.9.132 ✨ The model answers from a job's result.**
- Contract 2 step 3: `answer_from_job(request, job_reply)` sends the message, the job's reply text and its citation list, and asks for a short answer in CAIRN's voice that says when the result does not answer the request. The job's citations, proposals and actions are kept on the reply; the model's text replaces the body.
- Only for jobs whose `requires_ai` is false. A provider failure keeps the job's reply and adds the warning.
- Tests: a lookup miss becomes an answer that names the closest files; citations survive; a failing provider returns the job's text.

**V0.9.133 🔧 Greetings answered by the model.**
- `run_agent_with` and the router stop answering chatter themselves when a model is available: the loop (or one-job path) gets the message, and the persona already describes CAIRN's jobs. Without a model, `chatter_reply` answers as today.
- Tests: "salam" with a scripted provider calls the model; without a provider it gets the built-in reply.

**V0.9.134 🔧 A picked job runs inside the loop.**
- A capability picked from the + menu no longer skips the loop: the loop starts with an instruction that the person chose that job and must call its tool first, with the message as its argument; the model may follow up with other tools.
- The one-job path runs the picked job directly, as today.
- Tests: picking Summarize with a scripted loop provider calls the summarize tool first; a model that calls another tool first gets the error back and recovers.

**V0.9.135 🔧 Uploaded files go to the loop.**
- A message with `artifact_id` runs the loop with the file named in the first user turn (title and handle registered in the ledger), so "what is this file about" can read it, search beside it or compare it.
- Tests: a scripted loop reads the uploaded file by its handle; a viewer's upload still cannot propose.

### Track BB. Tools the model can use

**V0.9.136 ✨ File query sorting and size.**
- `ArtifactQuery` gets `sort: Option<ArtifactSort>` (`size`, `modified`, `created`, `title`), `descending`, `modified_after`, `modified_before` and `min_bytes`. `query_artifacts` builds the `ORDER BY` from a closed enum (no text from the request reaches SQL) and keeps the id as the tie-breaker.
- Tests: the largest of three files first, a date window, paging stable under the sort.

**V0.9.137 ✨ `query_files` tool.**
- A read atom in `loop_tools` and `cairn_tool_catalog`, also listed by `mcp_tool_specs`. Arguments: `text`, `kinds`, `folder`, `language`, `modified_after`, `modified_before`, `min_bytes`, `sort`, `descending`, `limit` (at most 40). Kinds and folders resolve like `list_files`.
- Each line: handle, path, kind, human size, modified date; then `Showing N of M files (X in total)`.
- Respects excluded folders (V0.9.93), quarantine and the workspace boundary like `list_files`.
- Tests: "largest file" script (`sort: size, descending, limit: 1`); a file in an excluded folder never appears; an MCP call lists it.

**V0.9.138 ✨ Groups and totals in `query_files`.**
- Argument `group_by` (`kind` or `folder`): one line per group with file count and total size, largest first, at most 20 groups; filters apply before grouping.
- Tests: two folders with known sizes; filters narrow the groups.

**V0.9.139 🔧 Tool descriptions written for the model.**
- Every loop tool's description gets the same four parts: what it does; use it when; use another tool when (naming the tool); what it returns. The jobs' `description` fields in `tools/mod.rs` and the atoms in `run.rs` both follow it; `routing_hint` derives from the same text so the one-job classifier reads the same guidance.

**V0.9.140 🔧 Misses that point the way forward.**

- Tests: a misspelled name gets the right file among the candidates; an empty workspace says so.

**V0.9.141 🔧 Loop instructions.**

## Excluded on purpose

- **A tool that runs commands or reads the disk.** File sizes come from the index (`size_bytes`), never from the file system; ADR 0006 keeps shell and outside effects away from CAIRN.
- **Plans, context compaction and sub-runs for long tasks.** Useful later; they do not fix tool choice and would make this line larger.
- **Choosing a model automatically by score.** The score is shown; people and administrators still choose.
- **Growing the keyword lists.** They stay as they are for the no-AI path.
