# Plan for the 0.11 line: polish before 1.0

Written 2026-11-25. Baseline: V0.9.69 (the 0.9 line closes with V0.9.119 after the CAIRN administration rows, the 0.10 pilot line runs V0.10.0 to V0.10.11). Scope is rows V0.11.0 to V0.11.68 in the [release index](../RELEASES_0.11.md) and the [roadmap](../ROADMAP.md#the-011x-line-polish-before-10). Why: the [polish review](../analysis/2026-11-25-polish-review.md).

This plan is written for the session that implements it. Each row below is one commit named `Update V0.11.N`, with the usual body (three or four `- ` lines), the version set with `npm run version:set -- 0.11.N`, the changelog, the user guide when something visible changes, and the roadmap, release index and mindmap rows updated together. Follow [CLAUDE.md](../../CLAUDE.md): no server, build, Vite or Tauri run; ask before `cargo check`, `cargo test` or `npm run typecheck`; run `cargo fmt --all` and clippy with `-D warnings` before a commit that touches Rust. The maintainer runs and tests the application.

## What this line is

The last minor line before 1.0. It **adds no new capability to the server**. It finishes what earlier lines left half done, closes what the review found, and makes the product faster and calmer to use. Three rules follow from that:

1. **A screen row uses routes that exist.** If a screen needs a route that is missing or wrong, the row says so and adds the smallest change, with its test. A new entity, setting or migration is not a polish change and needs its own row and the maintainer's agreement.
2. **Every row is something a person can try.** The changelog's *Try it* lines say where to click. Refactor rows say what must look and behave exactly as before.
3. **No ✅ without the walkthrough.** A row is 🧪 when committed and becomes ✅ only when the maintainer has tried it (V0.11.67 collects what is left).

**V0.11.3 📘 Route coverage check.**
- `scripts/check-routes.mjs` reads the routes declared in `apps/server/src/lib.rs` and the paths the client builds in `lib/api/` (template parts normalised to `{}`), and fails when a route is neither called nor listed in `scripts/api-only-routes.json` with a reason.

**V0.11.4 🐞 A crash never blanks the app.**
- One `ErrorBoundary` around the shell's content and one around each lazily loaded page and the CAIRN panel. A page that throws shows a panel in place of the page: what happened in one sentence, *Try again* (remounts the page), *Go to the dashboard*, and *Copy details* (message, page, version, time). The sidebar and top bar stay usable.
- A failed lazy chunk after a deployment (old `index.html`, new assets) offers *Reload* instead of an error.
- Test: a component that throws inside a page shows the panel and *Try again* remounts it.

**V0.11.5 🔧 Toasts with an action.**
- `showToast` takes an optional `{ label, run }`; the toast keeps its time-out and announces the action to screen readers.
- Use it for **Undo** after moving to the trash (restores), moving files (moves back), dismissing a review item, archiving a project (V0.11.17 uses it) and dismissing a CAIRN proposal.
- Test: Undo after a trash calls the restore route; a toast without an action is unchanged.

**V0.11.6 🔧 Request ids in errors.**
- A middleware gives every request an id (`X-Request-Id`, kept from a trusted proxy when it sends one), puts it in the request's log span and on every response.
- The client keeps it on `ApiError`; a toast for a server error (`5xx`) shows *Reference: abc123* with a copy action (V0.11.5), and the System › Logs search accepts it.
- Test: the id is on the response and in the captured log line; a `4xx` toast is unchanged.

### Track BE. Security

**V0.11.33 🔒 Two-step sign-in for administrators.**

- System › Users shows who is covered and not enrolled. The console's `users list` shows it too.
- Test: an admin past the grace period gets `mfa_enrolment_required` on an admin route and can still enrol.

**V0.11.34 🔒 Common passwords refused.**

**V0.11.35 🔒 Access token kept in memory.**

**V0.11.36 🔒 Nothing of one account left in the browser.**

**V0.11.38 🔒 Tamper-evident audit.**

**V0.11.39 🔒 Isolation headers.**

**V0.11.40 🔒 Unanswered questions without their words (CR-4).**

**V0.11.41 🔒 Sharing a chat says what it may show (CR-5).**

**V0.11.42 🔒 Daily cap on event routines (CR-7).**

**V0.11.48 📘 Bundle budget in CI.**

**V0.11.49 🔧 Static files cached and precompressed.**

**V0.11.50 🔧 Quick changes show at once.**

**V0.11.51 🔧 Prefetch on intent.**

- V0.11.2 and V0.11.3 come before any screen: the screens add to the area modules and remove their routes from the owed list.
- V0.11.5 (toasts with an action) comes before the rows that offer Undo (V0.11.15, V0.11.17).

## Excluded on purpose

New capabilities stay out of the polish line and are listed as 2.0 milestones in the review: passkeys, SAML and SCIM, live Drive/SharePoint/Slack sync, real-time co-editing, translations, mobile apps, PostgreSQL and object storage, an approximate vector index, CAIRN using outside tools, sprints and portfolios. A pilot finding that needs one of them is recorded and the 1.0 claim narrowed.
