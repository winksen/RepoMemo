# Plan for the end of the 0.9 line: administering CAIRN

Written 2026-11-26 for V0.9.70. Baseline: V0.9.69. Scope is rows V0.9.70 to V0.9.119 in the [release index](../RELEASES_0.9.md) and the [roadmap](../ROADMAP.md#the-09x-line-cairn-agent). It continues the [CAIRN harness plan](2026-11-22-0.9-cairn-harness.md), whose closing evidence row (V0.9.70) moves to V0.9.119. Decision: [ADR 0007](../../docs/decisions/0007-cairn-models-are-a-system-catalog-chosen-per-organization.md).

This plan is written for the session that implements it. Each row below is one commit named `Update V0.9.N`, with the usual body (three or four `- ` lines), the version set with `npm run version:set -- 0.9.N`, the changelog, the user guide when something visible changes, and the roadmap, release index and mindmap rows updated together. Follow [CLAUDE.md](../../CLAUDE.md): no server, build, Vite or Tauri run; ask before `cargo check`, `cargo test` or `npm run typecheck`; run `cargo fmt --all` and clippy with `-D warnings` before a commit that touches Rust. Errors and outcomes are toasts; greys are pure ([DESIGN.md](../../DESIGN.md)).

## Where CAIRN's administration is at V0.9.69

| Concern | Today | Where |
|---|---|---|
| Who configures the model | A **workspace** administrator adds text, vision and embedding providers in Settings › AI; CAIRN uses the workspace's first enabled text provider | `/v1/workspaces/{id}/ai-providers`, `crates/storage/src/providers.rs`, `apps/server/src/agent.rs:80` |
| Which model | One fixed `model` per provider; people cannot choose | `ProviderSettings.model`, `ChatOptions.tsx` shows it read-only |
| Agent mode | A `cairn_mode` flag in the provider's metadata, effective only for a tool-calling model | `apps/server/src/ai.rs:277` |
| Who may use AI | A minimum role per workspace (AI policy) and a monthly call limit per workspace | `ai_access.rs`, `/ai-limit` |
| Budgets and retention | Environment variables only: `REPOMEMO_CAIRN_MAX_STEPS`, `_MAX_RUN_SECONDS`, `_TRACE_DAYS`, `_BACKGROUND_MAX_FILES`, `_EVAL_PASSED_MODELS`, `REPOMEMO_AI_REQUESTS_PER_HOUR`, `REPOMEMO_BACKGROUND_AI_PER_DAY` | `apps/server/src/config.rs` |
| Instructions and procedures | `CAIRN.md` per workspace, playbooks per workspace, personal memory per person | V0.9.49, V0.9.54, V0.9.51 |
| An administration page | None. Settings are spread over Settings › AI, Profile, the upkeep switch and the environment | — |

The consequence: an organization of twenty workspaces configures the same model twenty times, holds twenty copies of one API key, cannot offer people a choice between a fast local model and a stronger cloud one, and cannot set a rule for CAIRN in one place.

## The contracts this part rests on

### 1. Who administers what

| Tier | Who | Administers |
|---|---|---|
| **Server** | System administrators, and people a system administrator makes **CAIRN administrators** (V0.9.71) | The model catalog (connections, keys, models, traits, evaluation, fallbacks), system caps on budgets and retention, every organization's CAIRN settings |
| **Organization** | Its owners and admins | Which catalog models the organization uses and its default, Agent mode, budgets and limits within the system caps, guardrails, abilities, instructions, the knowledge workspace, preference defaults |
| **Workspace** | Its admins | Which of the organization's models are offered and the workspace default, stricter guardrails, folders CAIRN does not read, which abilities are on, `CAIRN.md` and playbooks (as today) |
| **Person** | Everyone who may use AI | The model of a chat (from the offered list), preferences, personal memory (as today) |

App administrators read the CAIRN administration page and change nothing, as they do in System.

### 2. Inheritance

- **Models narrow downward.** Offered to a person = catalog models that are enabled ∩ enabled by the organization ∩ offered by the workspace ∩ allowed for the person's role (V0.9.87), with the workspace's AI policy applied first.
- **Limits tighten downward.** A system cap bounds the organization, which bounds the workspace. A lower tier can be stricter, never looser. A setting left empty inherits.
- **Preferences are defaults, not limits.** The organization sets defaults; a person's own choice wins (V0.9.114, V0.9.115).
- **Resolution of the model for a message:** the chat's chosen model if still offered → the person's preferred model for the workspace if offered → the workspace default → the organization default → none (CAIRN answers by its rules, as with no provider today). A refused or vanished choice is said in the chat, never silently replaced by a cloud model.
- The resolved text model serves CAIRN, Ask and summaries alike, so there is one text configuration. Embedding and vision models stay a workspace choice (changing them re-embeds or re-describes), picked from the catalog (V0.9.89).

### 3. Storage

| Table | Holds | Archives | Anonymization |
|---|---|---|---|
| `cairn_connections` | type, name, base URL, encrypted key (`REPOMEMO_SECRET_KEY`), locality, enabled, cloud acknowledgement | not in workspace archives (server level); in backups | n/a |
| `cairn_models` | connection, model id, display name, purpose, traits (tool mode, context, vision), evaluation, fallback, roles, enabled | as above | n/a |
| `organization_cairn_settings` | a versioned JSON policy (models, default, agent mode, budgets, guardrails, retention, preference defaults, instructions), `updated_by`, `version` | not in workspace archives | `updated_by` becomes *Former member* |
| `workspace_cairn_settings` | offered models, default, stricter guardrails, excluded folders, enabled abilities | **in** workspace archives; model ids unknown to the importing server are dropped with a warning | as above |
| `cairn_abilities`, `cairn_ability_versions` | name, command, description, instructions, tool subset, input fields, output template, scope (organization or workspace) | workspace abilities travel; organization abilities do not | author kept as *Former member* |
| `person_cairn_preferences` | model per workspace, language, length, steps shown, mode | personal: not in archives | deleted |
| `users.cairn_admin` | the flag | n/a | cleared |

Each write is checked with an `expected_version`, as tasks are (V0.7.6), so two administrators cannot overwrite each other unseen.

### 4. Guardrails, in the order a run meets them

1. Who may use AI (policy, role, model roles).
2. Which tools exist for this run (registry → organization switches → workspace switches → role; V0.9.91).
3. What the tools may see (excluded folders, V0.9.93; quarantine and untrusted marking as today).
4. What may leave the server (locality, secret and personal-data masking for cloud models; V0.9.94, V0.9.95).
5. How much (steps, time, tokens, per-person and organization budgets; V0.9.74, V0.9.96, V0.9.97).
6. What an answer may be (citation ledger, strict citations; V0.9.98).
7. What a change may be (proposal caps and typed confirmations; V0.9.92).

Every refusal names the tier that set it (*"Your organization turned off moving files with CAIRN"*), so a person knows whom to ask.

## Rows, one commit each

### Track AV. CAIRN administration

**V0.9.70 📘 CAIRN administration plan.** This planning change: this plan, ADR 0007, rows V0.9.70 to V0.9.119 in the release index and roadmap, the evidence row moved to V0.9.119, the 0.10 and 0.11 references updated. No code.

**V0.9.71 🔒 CAIRN administrators.**
- `users.cairn_admin` (migration), granted and removed by a system administrator in System › Users and with `users cairn-admin <email> on|off --yes` in the console; system administrators are CAIRN administrators by right. Audit events `cairn_admin_granted` and `cairn_admin_revoked`.
- `require_cairn_admin` (system or CAIRN admin, a session or a `system`-scope token) and `require_cairn_reader` (adds app admins, read only).
- Tests: a member is refused, a CAIRN admin is admitted, an app admin reads and cannot change.

**V0.9.72 ✨ CAIRN administration page.**
- Route `/cairn/admin/{section}` with sections Overview, Models, Organizations, Guardrails, Abilities, Memory, Usage and History, each an empty state until its row ships. Overview shows today's state read-only: each workspace's provider and mode, the environment budgets and retention.
- Organization owners and admins reach the page with only their organizations' sections (Organizations, Guardrails, Abilities, Memory, Usage); everyone else is refused.

**V0.9.73 ✨ Administration tab in CAIRN's sidebar.**
- CAIRN's sidebar gets two tabs, *Chats* and *Administration*; the second shows the page's sections as links, only to the people of V0.9.72. The palette gains *CAIRN administration*.
- Test: a member sees no tab; an organization admin sees only their organizations.

**V0.9.74 🔧 Run budgets as settings.**
- Steps, run seconds, run tokens, background files and trace days become run-time system settings (the existing `/v1/system/settings/{key}` mechanism) with the environment value as default, edited on Overview by CAIRN admins, bounded by fixed maximums. A change applies to the next run.
- Audit events with before and after.

### Track AW. Model catalog

**V0.9.75 ✨ Model catalog storage.**
- Migrations `cairn_connections` and `cairn_models` (contract 3), storage functions with versions, the key encrypted as provider keys are, `connection_id` deletion refused while a model is used anywhere. No route, no behaviour change.
- Tests: a key never appears in a read; a used connection cannot be deleted.

**V0.9.76 ✨ Connections.**
- Models › Connections: add, edit, turn off and test an Ollama, OpenRouter or OpenAI-compatible connection; the key is write-only; the existing endpoint policy and cloud acknowledgement apply (V0.9.81 shows locality). Routes `/v1/cairn/connections`.
- Tests: an address outside the allowed hosts is refused; a test reports reachability without the key.

**V0.9.77 ✨ Models of a connection.**
- *Find models* lists what the connection offers (Ollama `/api/tags`, OpenRouter and OpenAI-compatible `/models`); the admin adds chosen ones with a display name and purpose; *Test* fills tool mode and context size as Test connection does today (V0.9.35), and the admin may correct them. Routes `/v1/cairn/models`.

**V0.9.78 🔧 Providers moved into the catalog.**
- A migration turns every workspace provider into a connection (deduplicated by type, base URL and key fingerprint) and a model, keeps keys encrypted, and records which workspace used which model and its `cairn_mode`. CAIRN still resolves as before in this row.
- Test: an upgraded database has one connection per distinct endpoint and key, every workspace's model, and no key in clear.

**V0.9.79 ✨ Evaluation status per model.**
- The live evaluation runner (`npm run cairn:eval`, V0.9.46) can attach its report to a catalog model; the Models table shows passed, failed or not evaluated with the date. Agent mode is offered by default only for a tool-calling model with a passing report (the V0.9.47 rule), now read from the catalog; `REPOMEMO_CAIRN_EVAL_PASSED_MODELS` stays as an override.

**V0.9.80 ✨ Fallback model.**
- A model may name a fallback used when it times out, answers `5xx` or `429`. A fallback must be as local as the model (a local model never falls back to a cloud one) and offered to the person; the run's trace and the answer's model line say a fallback answered.
- Test: a failing scripted model falls back once; a local model with a cloud fallback is refused at save.

**V0.9.81 🔒 Local and cloud models.**
- Each connection's locality comes from its host (loopback or private is local, as in V0.9.36); a cloud connection needs the system's cloud acknowledgement before any organization can enable its models. Every list and picker shows *Local* or *Cloud*.

### Track AX. Models by organization and workspace

**V0.9.82 ✨ Organization CAIRN settings.**
- Migration `organization_cairn_settings` (contract 3) and `GET`/`PUT /v1/organizations/{id}/cairn` with `expected_version`; owners, admins and CAIRN admins may change it. Fields in this row: enabled models, default model, Agent mode default. Audit events.

**V0.9.83 ✨ Organization models on screen.**
- The admin page's Organizations section and Organization › Settings › CAIRN show the catalog's enabled models with their locality, evaluation and traits; the admin ticks those the organization uses and picks the default and Agent mode.

**V0.9.84 🔧 Workspaces inherit the organization.**
- CAIRN, Ask and summaries resolve their text model by contract 2 instead of the workspace's own provider. Each existing workspace starts with its former model offered and as its default, so nothing changes for anyone until an admin changes it.
- Tests: a workspace with no settings uses the organization default; one whose model the organization turned off falls back to the organization default and says so.

**V0.9.85 ✨ Workspace model list.**
- Migration `workspace_cairn_settings`; Settings › AI shows the organization's models marked *From your organization*, lets a workspace admin choose which are offered and the default among them, and never lists others. In workspace archives with the drop-unknown rule.

**V0.9.86 ✨ Model picker in the chat.**
- The model line under the message box becomes a picker of the offered models (name, *Local*/*Cloud*, *Agent* when tool-capable); the choice is per chat and stored on each turn; the server refuses a model not offered to the person.
- Test: a chat keeps its model; a removed model makes the next message use the default with a note.

**V0.9.87 🔒 Models by role.**
- A model can be limited to roles at the organization or workspace (*cloud models for editors and up*); the picker shows only permitted models and the server enforces it, after the workspace's AI policy.

**V0.9.88 🔒 Model boundary across workspaces.**
- A chat across workspaces (V0.9.60) sends a workspace's passages only if the chosen model is offered there to the person's role; the others are listed as found but not sent, as V0.9.61 does for providers. Test on the mock provider's request body.

**V0.9.89 🔧 Embedding and vision from the catalog.**
- A workspace's embedding and vision providers are chosen from catalog models of that purpose enabled for the organization; changing the embedding model asks before rebuilding vectors (`embeddings rebuild`).

**V0.9.90 🔧 Workspace provider forms retired.**
- Settings › AI no longer holds provider forms. `GET /ai-providers` returns the resolved view read-only; writes answer `410` with where to go. The API guide states the change; the console's commands follow.

### Track AY. Guardrails and limits

**V0.9.91 🔒 Tool switches.**
- The organization and the workspace can turn off any CAIRN tool or job by name (bulk trash, moves, notes, memory changes, task proposals, analysis, routines, MCP proposals). The registry builds each run's tools after the switches; the + menu and *what can you do* follow; a request for a turned-off job is answered with who turned it off.

**V0.9.92 🔒 Change limits.**
- Caps per confirmation (files moved or trashed, tasks created, cards changed; 200 by default as today) and the count from which the person types the number to confirm (V0.9.42), set by the organization and tightened by the workspace.

**V0.9.93 🔒 Folders CAIRN does not read.**
- A workspace admin marks folders as closed to CAIRN; search, read, list and analysis tools, chats across workspaces and MCP never return what is in them; the file browser shows a lock and the reason. Ask outside CAIRN is unchanged.

**V0.9.94 🔒 Secrets kept from cloud models.**
- Before text goes to a cloud model, detected secrets (private keys, provider and cloud keys, tokens, passwords in configuration, connection strings) are replaced with a marker; the organization chooses mask (default) or refuse to send. The trace counts what was masked, never the values. Pattern tests with true and false positives.

**V0.9.95 🔒 Personal data masking.**
- An organization option, off by default, masks email addresses and phone numbers for cloud models the same way, with the count in the trace.

**V0.9.96 🔒 Per-person CAIRN budgets.**
- Daily runs and tokens per person, set by the organization within the system cap; the composer says what is left when below 20%; administrators can be exempted. Counted from the stored runs.

**V0.9.97 🔒 Organization token budget.**
- A monthly token budget per organization across its models, with notifications to its admins at 80% and 100% and a choice at the cap: stop, or local models only.

**V0.9.98 🔒 Strict citations.**
- An organization or workspace setting: an answer about workspace content that cites nothing it read is not shown; CAIRN says it could not ground the answer and lists what it read. Greetings and in-character replies are exempt.

**V0.9.99 🔒 Routine limits.**
- The organization sets the number of routines per person and per workspace, the schedules allowed and whether event routines are on; existing routines over a new limit are paused with the reason, not deleted.

**V0.9.100 🔒 Retention by organization.**
- Trace, chat and personal memory retention per organization within the system maximum (V0.9.74); the maintenance sweep applies the shorter; the change is shown before it deletes anything.

**V0.9.101 🔒 MCP and inbox policy.**
- The organization can turn off the MCP endpoint and the inbox for its workspaces and set the inbox bound (50 today); a token's call into such a workspace is refused with the reason.

**V0.9.102 ✨ Usage and health.**
- The admin page's Usage: runs, tokens, failures, fallbacks, average steps and time per organization, workspace and model over 7 and 30 days, with CSV export. Aggregates only: no message, name of a chat or person below a group of five.

**V0.9.103 🔒 Administration history.**
- Every change made on the admin page and the organization and workspace CAIRN settings is an audit event with before and after (keys never); the History section lists them per scope, and System › Audit includes them.

### Track AZ. Abilities, memory and preferences

**V0.9.104 ✨ Abilities.**
- Migrations `cairn_abilities` and `cairn_ability_versions` (contract 3): an ability is a name, a `/command`, a description, instructions, the tools it may use (a subset of the registry), optional input fields and an output template, at organization or workspace scope. It never adds a tool, an external effect or a right the person lacks (ADR 0006, 2). Storage and API with versions.

**V0.9.105 ✨ Abilities on the admin page.**
- Create, edit, try (a run in a scratch chat of the admin's own, nothing kept), publish a version, turn off. The list shows who changed what and when.

**V0.9.106 ✨ Workspace abilities.**
- Workspace admins turn the organization's abilities on or off and add their own; enabled abilities appear in the + menu under their group and as `/commands` in the composer, with their description.

**V0.9.107 ✨ Running an ability.**
- `/command` or the menu runs the loop with the ability's instructions under the rules and its tool subset intersected with the run's tools; input fields are asked first; the trace and the answer say *Ability: Weekly status, version 3*. In Jobs mode the ability is shown as needing Agent mode.
- Tests: an ability naming a turned-off tool runs without it; a viewer's run of an ability gets no proposing tool.

**V0.9.108 ✨ Playbook to ability.**
- A verified playbook (V0.9.54) can be turned into a workspace ability in one step, keeping a link both ways; the playbook stays.

**V0.9.109 ✨ Organization instructions.**
- Instructions for CAIRN at organization level, read into every run of its workspaces above the workspace's `CAIRN.md` and below the system rules, capped like `CAIRN.md`, versioned with their author, shown in the trace as *Organization instructions, version N*. They cannot change rights, tools or policy.

**V0.9.110 ✨ Organization knowledge workspace.**
- An organization may name one of its workspaces as its knowledge workspace: its verified memory cards and playbooks are offered to CAIRN in every workspace of the organization, **only for people who can read it**, labelled with where they come from.

**V0.9.111 🔒 Personal memory policy.**
- The organization turns personal memory on or off and caps its entries; people see the policy in Profile; turning it off stops reading it into runs and offers each person to export or delete theirs. Nothing is deleted without them, except by retention (V0.9.100).

**V0.9.112 ✨ Memory overview.**
- The admin page's Memory section: per workspace, memory cards by state, upkeep findings open, playbooks unused for 90 days and corrections waiting; links go to the workspace's own pages. Turning memory upkeep on for several workspaces at once. Counts only for workspaces the admin can read.

**V0.9.113 ✨ Routines overview.**
- The admin page lists routines in the organization with owner, schedule, last run and state, and can pause and resume one, without reading its prompt or its answers.

**V0.9.114 ✨ Personal CAIRN preferences.**
- Profile › CAIRN: the preferred model per workspace (from the offered list), answer language, length (brief, standard, detailed), steps shown open or closed, Agent or Jobs when both are possible. Migration `person_cairn_preferences`; read into runs as settings, not as memory.

**V0.9.115 ✨ Organization preference defaults.**
- The organization sets the defaults of V0.9.114 for people who have not chosen; Profile shows which values are the organization's.

**V0.9.116 ✨ Greeting and starter questions.**
- The organization and the workspace can write CAIRN's greeting line and up to six starter questions, used in place of the template's suggested questions (V0.9.7) when set.

## Excluded on purpose

- **Abilities that call outside services** (HTTP actions, outside MCP tools, scripts): ADR 0006 keeps external effects away from CAIRN in this line.
- **Per-person money accounting and invoices**: usage is in calls and tokens; pricing is not stored.
- **Admins reading people's chats or traces**: they see aggregates and settings, never conversations.
- **A different persona per organization** (another name than CAIRN): only the greeting and starter questions are customised.
